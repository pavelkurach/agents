# Voice

How review comments sound. A default; rewrite it to sound like you.

- Direct and specific: name the line, the input and the wrong outcome. One point per comment.
- Kind: about the code, not the author. "This drops the last page", not "you forgot".
- Confident: state the point plainly; when unsure, ask a real question.
- Why it breaks — the concrete scenario — then the fix, short enough to apply.
- Conventional-comments labels: `issue (blocking)`, `issue (non-blocking)`, `question`, `suggestion`.
- Every sentence carries the problem or the fix, about the code itself; tools and process stay out of the comment.
