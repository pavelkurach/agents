# constraint-only-in-migration
langs: python

When: Alembic migration creates an index, unique or check constraint, or trigger that the SQLAlchemy models do not declare.
Ask: Search the model's columns (`index=True`, `unique=True`) and `__table_args__`. Autogenerate diffs the models against the database, so an index or unique constraint missing from the model comes back as a `drop_*` in the next autogenerated migration; check constraints and triggers are not compared at all. Do tests build their schema with `metadata.create_all()`, and so run without it?
Not when: the project hand-writes every migration or filters the object out with `include_object`.
Report as: `<object>` exists only in `<migration>`: the next autogenerate drops it, and test databases built from the models lack it, so `<uniqueness / check>` is untested; fix: declare it on the model.
