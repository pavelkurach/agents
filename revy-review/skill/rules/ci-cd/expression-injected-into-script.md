# expression-injected-into-script
langs: github-actions

When: `${{ }}` expression in a `run:` script or `actions/github-script` `script:`, in a workflow or composite action, reading event data, `github.head_ref`, a step output or a composite action's `inputs.*`.
Ask: Can anyone outside the maintainers set the value? Actions substitutes `${{ }}` into the script text before the shell or Node parses it, so the value runs as code. Attacker-set fields include issue and PR `title` and `body`, comment and review `body`, `head_ref`, `head.ref`, `head.label`, `head.repo.default_branch`, commit `message` and author `name` and `email`, and `pages.*.page_name`; git ref rules and email syntax do not stop it (`zzz";echo${IFS}"hello";#` is a valid branch name), and a step output derived from one carries it. What does the job hold? On `issue_comment`, `issues`, `push`, `pull_request_target`, `workflow_run` and same-repository `pull_request` it has the referenced secrets and a token that may write; a fork's `pull_request` gets a read-only token and no secrets. A value passed through `with:` is an argument, not script text, unless the action itself evaluates it as a template or code.
Not when: ids no user sets (`github.event.number`, `github.sha`, `github.repository`, `github.run_id`) · the value reaches the script only as a quoted environment variable set in `env:`.
Report as: `<expression>` is spliced into the script of `<step>` on `<event>`: whoever sets `<field>` runs commands with `<secrets / write token>`; fix: set it in the step's `env:` and use `"$VAR"` (`process.env.VAR` in github-script), with no `${{ }}` inside the script.
